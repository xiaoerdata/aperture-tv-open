# 让旧电视有一条不用网页的首页

源码新增本机首页选择与渲染进程退出回退。此页说明开发实现；是否已经收入APK，以[私有下载索引](DOWNLOADS.md)和该包来源为准。Android 8 / API 26仍为安装下限，不能由此推及Android 4–7。

## 两个设置，各管一件事

- **玻璃 / 简洁本机首页**：设置在电视的入口设置或家人设置。简洁首页使用Android原生按钮，不创建首页WebView，不加载首页背景图、字体或轮播。保存到当前版本本机；标准版和爸妈版各自独立。
- **轻量 / 完整家庭窗景**：进入家庭服务后的内容界面。手动选择简洁首页不会清除家庭地址、配对、NAS连接、来源绑定或应用快捷，也不禁用家庭网页。

二者均不改变系统默认桌面，不接管开机和Home键。简洁首页可以减少首页网页负担；没有实机内存、帧率或耗电数据，不宣称具体性能收益。

## 自动选择

| WebView状态 | 本机首页 | 家庭内容 |
| --- | --- | --- |
| 无法确认 / 低于37 | 原生简洁首页 | 不尝试家庭网页；可用原生NAS和已安装应用 |
| 37–88 | 原生简洁首页 | 保留原有ES5轻量家庭屏；网页影院仍需89+ |
| 89+ | 默认玻璃首页；家人可选择简洁首页 | 按家庭屏设置和版本判断 |
| 当前Activity收到渲染进程退出 | 原生简洁首页 | 本次不重建家庭WebView，避免Home/重试形成循环 |

版本只是实现的路由规则，不是这些WebView版本或电视型号已实测兼容。浏览器访问`/home`的网页预览也不等于Android原生简洁首页。

旧实现用37作为玻璃首页门槛，但首页样式使用较新的flex间距、八位十六进制颜色和clamp等能力；只验证JavaScript ES5不能证明整体界面兼容。现将玻璃首页门槛与完整界面对齐至89，不强迫旧内核渲染该界面。原有轻量家庭屏仍保留。

## 网页显示组件退出时

MainActivity的`onRenderProcessGone`只清理对应的当前WebView：关闭家庭代理、撤销生命周期回调，先移出视图树再destroy，不在失效实例上stopLoading或继续导航。迟到的旧页面回调不能清理新的页面。用户偏好不被自动改写；这一恢复状态只属于当前Activity。

此时仍可进入本机应用、原桌面和原生NAS。家庭网页及地址配置会说明暂不可用，不自动重新创建网页。按Home、返回或切换首页偏好不会解除本次恢复状态。需要再次尝试时，在系统应用设置中结束开窗后重开，或重启电视；单纯回到首页并不等于完全重开。

这只处理Android向Activity报告的渲染进程退出。它不是Java进程崩溃、系统OOM或所有厂商WebView缺陷的通用恢复器，也没有实际杀死电视渲染进程的验收证据。

## 复现与验收

`node --test tests/lobby-mode.test.mjs tests/playback-session.test.mjs tests/android-source.test.mjs`运行生产Java路由、播放中断及来源验证。`node scripts/check-native-compat.mjs`只进行两版API编译与既有资源/生命周期验证，不生成APK。

`node scripts/browser-home-mode-qa.mjs`在桌面Chromium模拟APK内置HTTPS源，检查两版设置的遥控按键入口、可见焦点、固定`aperture://action/home-mode`请求及返回焦点。它不执行Android Intent、原生对话框、偏好持久化或Renderer退出回调，不把UA仿真当成真正旧WebView。

真机后续记录：型号/固件/实际WebView；默认选择；手动切换后完全关闭再打开；原应用/NAS/原桌面；无菜单键时的家人设置；标准/爸妈设置独立；旧内核家庭轻量屏；进入家庭网页后的中断、Home与恢复；两小时运行。使用测试内容，避免录下真实NAS资料或配对码。


## v11：保留原系统桌面

默认作为普通应用安装，不加入可用HOME候选。需要替换桌面时，在默认桌面设置内主动开启，再由系统选择；可移除本版候选。v10已有开窗默认项需重新选择，家庭/NAS数据不应清除。[兼容边界与真机清单](XIAOMI-COMPATIBILITY.md)。
