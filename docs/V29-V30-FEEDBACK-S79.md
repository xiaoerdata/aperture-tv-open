# v29 / v30反馈处理

本轮为v30（0.2.0-alpha.27）；公开状态以Release与独立下载回读为准。报告设备为MiTV-MTEQ0、Android 10、1920×1080、密度320；开发模拟器和浏览器不能代替该设备验收。

| 反馈 | 实现 | 验证位置 |
| --- | --- | --- |
| F01 选集栏过宽 | 以屏幕像素计算，选集栏33%宽；其他选项36%，避免密度320重复放大 | `CinemaChoicePanel`，原生系统输入回归 |
| F02 失败后跳集 | 候选线路始终按最初选中的集名匹配；单集线路不能扩大到其他集 | `CinemaPlaybackPlan`，`ReleaseReadinessTest`单集陷阱反例 |
| F03 首次点击只聚焦 | 触摸抬起时提交一次；取消、移出和父滚动拦截不提交 | `TvUi.touchClick`、海报与播放器按钮；系统触摸回归 |
| F04 目录超时阻塞片单 | 默认优先本地片单；本地切换不排队等待远程任务；错误标明来源并保留本地入口 | `CinemaBrowse/CinemaActivity`，延迟14秒合成来源 |
| F05 混合栏目 | `section`数组或`sections`声明栏目，每项`section`明确归属；先筛选再分页 | Java/Node契约、schema、混合样例与持久化回归 |
| F06 海报过密 | 四列，保留标题、年份/类型、更新信息、评分角标及来源 | 原生片单截图 |
| F07 片单资料 | 保留已有`cover/plot/metadata`，补充`poster/summary`别名、数字年份与评分；冲突拒绝 | Java/Node双端、真实WebP/JPEG解码另验 |
| F08 本机控制 | 默认关闭的限时HTTPS配对、语义树、自身截图、内部按键、直接导包和解码首帧探测 | [局域网指引](LOCAL-TV-CONTROL.md)，TLS证书先验测试与原生配对回归 |
| F09 短集名占位过大 | 8字以内使用三列紧凑网格；长标题整行换行；保留20集分组 | 短集名/长标题原生系统输入 |

## 核对报告结论

片单资料并非此前完全不存在：已有版本支持`metadata`和`cover/plot/rating`。本轮改善常见写法和数字输入，避免Agent因字段名称误解而另搭目录代理。已有文本评分保持兼容。带明确年份的自动资料匹配不接受未知年份或相差超过一年候选；未声明年份仍按既定偏好选择合理的新版本。

WebP不能一概视为不支持；Android现有BitmapFactory能解码WebP。资源失效、响应类型、请求头、解码与图片绑定需要分别检查。没有把所有图片改成JPEG或宣称外部全部海报可用。

不采用报告中的默认匿名读取、跨应用截图或受保护画面捕获。配对码后仍需电视确认；本机凭证不授予Hub产品权益。mDNS先查服务，缺主机地址时补查A记录；解析/缓存均有上限。3秒同网发现和5秒推包属于真机指标，不能用本机夹具替代。

## 首页兼容回退（P80）

用户确认看到纯色、大按钮首页。对比v28与v29公开提交，主玻璃首页的风景素材仍在，`LobbyMode`的WebView89门槛没有在v29新增；旧内核、手动选本机首页或渲染退出会走纯色本机路径。具体电视内核版本未读取，因此不能断言由哪一个触发条件进入，但外观差异与该路径一致。

本轮保留主玻璃首页，不降低内核门槛、不反复重启崩溃渲染器。本机路径改为`ScenicNativeHome`：随安装包离线提供风景、深色遮罩、大时间日期、四个观看入口和向下翻页的应用/工具；爸妈版已配置的常用应用仍在首屏，尺寸小于观看入口。本机模式使用采样的静态玻璃背景，不依赖实时GPU模糊或网页内核，不宣称具有玻璃首页全部动效与家庭面板。家庭网页错误也在风景首页上展示提示。

本机模式可在应用/工具更换四套摄影壁纸，单独保存选择；网页模式原有壁纸偏好保留，两者不冒充已自动同步。所有原系统、小爱与米家入口和权限保持原有边界。
