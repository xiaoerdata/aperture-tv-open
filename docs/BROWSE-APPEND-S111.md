# 片单原位加载下一页

> 本文保留该阶段的开发记录，改动已合入v43；安装与验收范围见[v43说明](RELEASE-V43.md)。

P126要求下拉加载时只出现加载符号，列表直接增长，不跳出当前界面。本轮修改标准版源码，未打包上传，爸妈版暂停。

## 改动

旧代码从底排向下调用 `videos()`，又经过通用 `task()` → `screen()`，先换成“正在读取”的页面，成功后重建片单。现在首次进入与下一页使用不同流程：首次进入仍可显示读取状态，后续分页只更新当前列表。

- 到最后一排时提前请求下一页；底排向下也能触发，无须点击“加载更多”。重复按键和预取共用一个在途请求。
- 页面底部预留固定高度，读取时仅显示小型转圈；成功后隐藏。网格、已有影片、海报和焦点对象保留，新增影片通常接在下方。
- 保持“最新时间/豆瓣评分”对已加载内容的排序。新影片若需要插在前面，通过原网格的行列位置调整，不重建旧海报，并按当前可见影片恢复画面位置。分页不会强行将焦点移到首项，也不会抢走来源侧栏的焦点。
- 失败保留全部已加载影片，仅底部显示“加载失败”和“重试”；继续按下也可重试相同的下一页。正常状态没有单独的加载按钮。
- 筛选后暂时为空时，空态也能用向下键继续请求后页。到末页停止请求；重复条目按ID去重，保留既有2000部预算。
- 切换来源、分类、排序、搜索或退出页面会使旧请求失效。暂停时取消在途分页并停止该次请求，迟到响应不能追加到新片单。

`CinemaBrowsePanel`管理原位网格、底部状态与可见锚点，`CinemaPaging`管理单个请求与合并预算；`CinemaActivity`装配来源请求，不再用整页任务流程加载下一页。首次进入、主动切换筛选/排序或从其他页面返回仍可重新建立片单；“不重建”专指当前列表的追加过程。
