# 播放进度与线路记忆

> 本文保留该阶段的开发记录，改动已合入v43；安装与验收范围见[v43说明](RELEASE-V43.md)。

标准版源码更新，尚未打包上传。现有公开包不包含本轮改动，爸妈版暂停。

## 行为

- 每部影片保存最近一次观看的集数、播放位置和成功播放的线路。详情页与收藏概览共用恢复逻辑，下次优先回到上次的线路和集数。
- 沿用15秒检查点，暂停、离开页面、切换播放和销毁时保存；系统强制停止或断电后，以最后成功写入的位置为准。实际写入失败会显示记录未保存的提示，不假称成功。
- 看完后重开仍选择上次线路和集数，从头播放；用户主动选择其他集数时，不把上一集的进度带过去。切换线路和自动故障切线继续沿用当前集数及位置。
- 线路重排按来源中的线路名称恢复；原线路移除时，仅尝试当前来源里能明确匹配同一集的线路。集数名称允许明确的数字形式变化和完整长标题，匹配不明确时不猜。全部无法匹配时保留可用入口并从头开始。
- 直播频道的线路以“线路1、线路2……”记忆；切台后再回来及重开会优先采用该频道的上次线路。“切换线路”在播放器菜单中可用。来源减少线路后越界会回到第一条。直播不保存可回看进度，也不声称支持直播时移。
- NAS继续使用统一观看记录，本轮验证其续播、收藏、并发更新与清除记录没有被影响。

观看记录按来源与影片ID隔离，保存在现有本机加密存储，不缓存临时播放链接。清除观看历史也会清除对应进度和线路记忆，收藏与追剧保留。此处记住的是每部影片最近的一次观看，不是每一集各自的一份永久进度档案。

## 修复的缺口

旧 `CinemaShelf.watch()` 使用 `duration` 保存毫秒时长，而影片资料的 `duration` 表示“96分钟”等文本。资料刷新、收藏更新等调用会覆盖这个字段，导致原续播检查得到0。现在播放时长单独存为 `playDuration`，`duration` 只保留展示资料。

已有数字时长自动迁移，已有位置在旧时长被资料覆盖时也保留；最终跳转仍由真实播放器准备后按实际总长限制。缺少或接近片尾的有效进度不会跳到影片末尾。新模型读取旧记录，不清空用户历史。

原详情恢复仅在“未看完且线路/集数原文完全相同”时选择上次线路，已看完会回到首条；收藏概览有另一套选择循环。现在统一为 `CinemaResume`，覆盖已完成记录、线路重排/移除和明确集数别名。只记源内身份和名称；无稳定线路ID的来源若任意改名，不能保证识别为原线路；直播线路序号也随作者提供的顺序解释。

## 验证

`python3 scripts/s110-playback-memory-test.py` 执行生产领域代码：

- 36项播放记忆检查：真实临时文件写入并重新读取、元信息与进度隔离、线路排序变化、集数变名、不同集数与来源隔离、匹配歧义、看完/从头、旧记录迁移、直播线路和清除记录。
- 5项既有收藏概览回归。
- 31项既有NAS统一观看回归，包括并发更新、失败事务和JVM AES-GCM往返。

另有121份原生源码编译及29项尺寸案例通过。这些检查不执行Android MediaPlayer、AndroidKeyStore或小米遥控器，没有把模型测试当成播放器实际跳转验收。临时文件与编译类自动清理，保留精简回执。
