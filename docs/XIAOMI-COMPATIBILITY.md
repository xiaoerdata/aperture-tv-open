# 小米电视兼容检查

目标是保留原系统使用习惯，额外提供家庭信息、NAS和个性化入口。Android 8+只是安装下限，不代表每台小米电视都已适配。当前没有小米实体电视验收结果。

## 默认作为普通应用

从源码 v11 起，安装后不注册可用的 HOME 候选，不申请开机启动，也不替换原桌面。两个历史安装包各有一个默认关闭的 HomeEntry；当前仅迭代标准版。在设置首项「默认桌面与开机」中选择「设为默认桌面」，开启本版 HOME 候选并进入系统授权。Android 10 及以上优先请求系统 HOME 角色，未支持时打开系统桌面设置。返回设置面板后重新读取实际默认项；取消授权不会显示为已设置。

系统支持第三方桌面时，开机和 HOME 由系统进入开视；HOME 到达已有任务后回到开视首屏。部分小米固件固定使用原桌面，或单独接管 HOME / 开机行为；普通 APK 无法保证覆盖这些限制。开视不通过修改分辨率、密度、停用小米桌面或后台循环拉起来取得接管效果。

首屏按返回显示「返回系统原生桌面？」；默认焦点是「留在开视」。应用页、内容页和弹窗先返回上一层。「返回原桌面」通过保存或选择的原桌面组件打开原系统，不修改默认项；已将开视设为默认时，之后按 HOME 仍会由系统回到开视。

要恢复原桌面为默认，在「默认桌面与开机 → 系统桌面设置」中选择原桌面。开视仍是默认时不直接移除候选，避免产生无默认桌面的中间状态。更换后「取消桌面候选」只停用本版 HOME 入口，普通应用入口和用户数据保留。

**v10及更早版本升级：**以前 MainActivity 自带 HOME 过滤器，新版改为独立别名。原先把开视设为默认桌面的用户需要重新主动开启和选择。新别名默认关闭；此前保存的家庭服务、NAS和首页样式不因此清除。不要为升级先卸载。

## 原生生态边界

| 项目 | 实现与当前证据 | 小米真机验收 |
| --- | --- | --- |
| 原桌面与 Home 键 | 独立可撤销 HOME 别名；仅系统公开设置；Android TV模拟器可核验候选与默认解析 | 安装、升级、开启、移除后分别按 Home；检查原桌面、系统设置和卸载后的默认行为 |
| 小爱语音键 | ASSIST、VOICE_ASSIST、SEARCH、HEADSETHOOK走系统；无麦克风或热词权限；有源码/API与浏览器契约检查 | 原桌面和开视分别长按、松开，检查持续监听、语音搜索和焦点返回 |
| 远场与待机唤醒 | 由硬件和原固件负责，无常驻唤醒服务 | 原系统支持的条件下对照测试；不能用模拟器通过替代 |
| 音量、电源、输入源 | 没有接管这些按键或更改电源设置 | 实体遥控音量/静音/电源、HDMI切换与返回；原生浮层应能显示 |
| 小米账号 | 只打开原系统公开账号设置；不读取、同步或接管账号凭证 | 已登录状态、账号设置可达性、切回原系统后状态一致 |
| 米家 | 自有HA通过官方Xiaomi Home独立授权；只读实体、手动选择分享；不调用家电控制 | 原有米家设备和自动化仍可用；撤销HA授权后读取失败；检查分享快照过期与移除 |
| 播放中断 | NAS窗口/音频焦点丢失时暂停，不自动续播；已有纯Java合成端口验证 | 实际播放时唤醒小爱、切应用、待机；检查暂停与主动恢复，无重叠声音 |
| 两版与本地数据 | 独立包、独立偏好；不读取其他应用数据 | 覆盖升级保留家庭/NAS设置、两版独立；返回原系统仍可用 |

源码v13的Manifest申请INTERNET、REQUEST_INSTALL_PACKAGES与REQUEST_DELETE_PACKAGES，后两项仅用于人或已授权WorkBuddy发起原生安装/卸载确认；不是静默安装或删除权限。应用无账户读取、无障碍、系统设置写入、开机广播接收器或后台服务。v15为用户明确导入的HTTP媒体开启应用cleartext标志；家庭凭证交接仍要求可信HTTPS，NAS和家庭服务校验未放宽。内嵌播放器和HTTP后续请求边界见EMBEDDED-CINEMA.md，当前未完成小米播放验收。

## 实机记录方法

先在原系统记录同样操作的结果，再安装新版对照。填写型号、固件、Android/WebView版本、遥控器类型、测试包版本与签名；不采集序列号、账号、家庭录音或NAS口令。分别记录通过、失败、未测，任何默认桌面无法返回、语音被吞或原系统账号异常都应阻止公开推荐该机型。

无须先启动电脑家庭服务，即可检查普通应用启动、原桌面、小爱按键和系统快捷入口。米家分享与家庭内容另按 [米家接入](XIAOMI-HOME.md) 检查；NAS按 [NAS指引](NAS.md)。本页是验收清单，不是小米官方认证或全机型承诺。

### 默认桌面与返回的本轮待验项目

在电视原有显示设置下测试，不调整系统分辨率或密度：

1. 首屏按返回，仅出现一次确认框；默认焦点为「留在开视」。取消后焦点可继续移动；从应用页返回先回首屏。
2. 设置首项进入「默认桌面与开机」。取消系统授权后仍显示未设置或等待选择；授权成功后显示「已设为默认桌面」。若系统拒绝或没有入口，记录实际状态，不记为通过。
3. 在片库、应用页、设置和退出确认框分别按 HOME，应回到开视首屏；观察任务和 Activity 数量不持续增长。HOME 是否由系统交给开视与 `onNewIntent` 收到后是否归位分开记录。
4. 冷启动电视和待机唤醒分别测试；只有系统实际进入开视，才记录对应能力通过。待机恢复不等同于冷启动。
5. 从首屏确认返回原桌面，原桌面应可操作；再次按 HOME 返回开视。随后在系统设置中改回原桌面默认，再取消开视候选，验证原桌面、开视普通应用入口和数据均正常。

浏览器入口与焦点检查：`CHROMIUM_PATH=/path/to/chrome node scripts/s90-home-settings-test.mjs`。此检查不操作 Android 默认桌面，不验证开机、小米 HOME 或原桌面交接。
