## 关键取舍

1. 家庭电视是共享屏幕：个人原始数据不自动流向客厅。MCP摘要可控分享；上游返回的指令不成为执行依据。
2. 用户希望日常更新交给助手：先打通场景/标题/留言/日程/指标闭环，手机保留授权、撤销和尚未Agent化的功能。照片、生活数据自动分享策略和影院管理尚待扩展，不在文案中假装完成。
3. 公开自托管协议与平台商业入口分开：当前可运行本机助手；Hub付费权益未接通，/agent保持禁用，私有脚手架不导出。
4. 局域网不是身份证：IP只增加来源约束，令牌和scope仍需逐次校验；真实反代必须覆盖可信来源并限制入口。换IP会要求重配，这是当前明确的体验代价。
5. 玻璃体现控制层层次：内容要看清，电视要能跑。实现局部浅色材质和实底降级，不模拟全屏高成本折射。

## 遇到的具体问题与修正

- QR挑战加入后，旧测试只传六位码，审批返回403。更新CLI、手机链接处理、调用方与测试，并增加缺少挑战和来源变化拒绝断言。
- 未登录扫码的浏览器测试最初找不到可见管理口令框：管理员表单在折叠区内。扫码请求现在自动展开该入口、提示登录后继续，正常登录后定位到助手授权，不自动批准。
- 批准后仍显示空的授权表单，容易误以为还要再填一次。改为隐藏已消费表单，保留成功反馈和设备撤销入口。
- HLS播放器动态加载可能在用户切换影片后继续旧请求。以播放代次识别过期加载；代理头部超时与长流生命周期分开。
- 浏览器缺H.264解码支持，改用VP9媒体fixture验证真实播放；导出传播视频仍是ffmpeg生成的H.264，二者证据分开。
- 某连接器许可文件为小写license，首次未找到不能推断“无许可”。补查后记录MIT；小米HA桥的非商业自定义许可不当作通用开源许可。
- 早期手机首屏截图受平滑滚动影响停在安装步骤，改用瞬时回顶重新截图；完整页面与局部展开都保留。

## S09 · Android实际按键入口与私有安装候选

继续按P10推进安装验证，检查到原生外壳只发送KeyboardEvent.key，而轻量页只读keyCode/which；此外synthetic Enter不会自动激活链接。这会使模拟电脑键盘通过、真实Android入口却失效。
