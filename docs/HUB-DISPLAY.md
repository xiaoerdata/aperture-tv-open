# 智小策 Hub 接入预留

当前状态：开视两版设置和原生菜单已有“智小策 Hub”入口；玻璃页“扫码登录”不可用，显示连接服务尚未接入。没有调用 Hub 登录、发放账户凭证、显示假二维码或读取任何账户数据。下面是待实现的接入约定，不是已上线接口。

人通过 Hub 原账户扫码并选择电视展示范围。二维码只携带短时、一次性的登录申请，不能包含用户令牌。电视凭证由原生端加密保存，不写入网页 localStorage、二维码、URL 或日志；设备可在 Hub 账户中心单独撤销。家庭服务管理员会话不能冒充 Hub 会话。

启用真实账户前，凭证还须与第三方插件隔离：当前JAR/Python插件和开视使用同一Android UID，KeyStore加密本身不能阻止同UID代码使用凭证。接入实现应采用独立UID的账户代理或等效权限隔离，通过只读摘要通道向电视提供获准内容；不能仅把令牌从网页移到原生存储就视为完成隔离。

## 拟定流程

1. 电视向已配置的官方接入服务申请设备登录：服务返回申请编号、验证链接、过期时间与轮询间隔。
2. 用户用手机登录 Hub，核对电视名称与验证码，选择电影、体重、旅行、账本中的展示范围并确认。
3. 原生端按服务指定间隔查询，只接受本次申请结果；超时/取消清除申请，不自动反复新建。TLS 和可信服务地址的校验必须在提供真实二维码前完成。
4. 接入服务每次读取重新校验账户、产品权益、设备授权、范围、到期及撤销；给电视最小化展示摘要，闭源应用源码/业务数据库不进入开源项目。
5. 电视只把仍有效且已获展示授权的摘要交给首页。本地退出、收到撤销、过期或校验失败后清除旧摘要；远端撤销在下一次校验或推送到达时生效，断网时按有效期撤下，不能宣称离线即时获知撤销。不同账户不能共享缓存。当前本地 NAS、家庭来源保持各自权限。

这是一条人类授权的只读展示通道。它不会授予 Agent 自动化权益。后续 WorkBuddy / MCP 操作仍须通过 Hub 专用入口，逐请求验证独立 Agent 权益、产品权限和范围；令牌统一在 Hub 个人中心管理，私有 Skill 和工具 schema 不进入公开静态资源。

## 展示模型草案

公开的 [展示摘要 schema](contracts/hub-display-v1.schema.json) 仅描述渲染数据，不包含登录秘密、内部数据库结构、机器工具 schema 或私有业务 API。

| 分区 | 可选摘要 | 默认限制 |
| --- | --- | --- |
| 电影 | 最近记录、想看、已看状态 | 不自动同步第三方影视站令牌或播放地址 |
| 体重 | 最近一次记录、更新时间 | 用户单独允许后展示，不默认向家庭公开 |
| 旅行 | 下一次行程、日期、目的地摘要 | 不含证件、订单或精确实时位置 |
| 账本 | 本期收支摘要、记账状态 | 需要单独确认共享金额，不导入逐笔账单 |

每份快照有单调 revision、过期时间与最多12张卡；每卡有稳定id、类型、短文案、更新时间和过期时间。不接受HTML、脚本或任意跳转URL。真适配器实现时还须执行格式、时钟、字段长度和revision检查，schema文件本身不是授权检查。

渲染schema不承载账户凭证。原生适配器须把快照绑定到当前账户、设备授权和会话代际；账户切换、取消或获知撤销时递增代际并清空Hub缓存，拒收旧请求的迟到回包。revision只在同一授权上下文内比较，不能跨账户复用。每类内容使用独立且稳定的卡片ID，拒绝重复ID，并在渲染、定时刷新和恢复前台时同时核对快照与卡片有效期。该适配器尚未实现。

没有配置时首页不展示 Hub 占位数据。后续映射复用家庭摘要的轮播/静态/隐藏选择；源错误不能被显示成“已连接”。首期设计为只读，不从电视修改体重、账本或旅行订单。

## 上线前验收

扫码同意/拒绝/超时/重复确认、设备撤销、账户切换、不同家庭隔离；产品权益过期；投影过期、乱序与重复回包；手机与电视数据一致；原生密钥保护和日志脱敏。完成服务端实现及这组验收后才能启用“扫码登录”。本轮没有修改、部署或发布 Hub。
