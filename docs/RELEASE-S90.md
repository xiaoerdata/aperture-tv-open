# v34 标准版：启动、显示与默认桌面

版本 `0.2.0-alpha.31` / versionCode 34，仅小米电视 Android 8+。爸妈版暂停更新。

v33 在小米 85 QLED 默认 density 320 下仍不可用，本版不把上一轮浏览器通过当作已修复证明。

## 本次修改

- 阻止屏保在首页脚本加载完成前发起原生导航；原生焦点握手后才同步状态，并跳过重复通知。
- 画布按实际 CSS 可见视口及 WebView 页面比例缩放；不修改电视分辨率、密度或字体。
- 启动检查遥控和缩放 API，异常时退到已有本机风景首页；记录有限的显示和控件诊断。
- 首屏返回先询问是否回原桌面。设置首项提供默认桌面与开机，申请系统 HOME 授权并显示真实状态；系统把 HOME 交给开视后回到首屏。

## 验证与限制

[启动三组对照](verification/s90-packaged-startup-browser.json)：v33 原包在 appassets 地址的桌面 Chromium 测试中，提前跳转后出现时钟横杠、API缺失与按钮未绑定；只替换屏保守卫即恢复。

[5组视口检查](verification/s90-viewport-browser.json)、[16组确认键](verification/s90-home-watch-confirm-browser.json)、[设置入口](verification/s90-home-settings-browser.json)、[Android WebView](verification/s90-webview-native.json)。原生测试使用 Android28 / WebView66，旧版最终也正常，因此不能据此声称已在小米内核复现并修好。该测试使用省略大图字体的隔离诊断包，并绕过产品玻璃首页要求 WebView≥89 的入口门槛，不属于完整产品验收。

默认桌面、开机进入、HOME分发和显式返回原小米桌面依赖固件，开发环境尚无这台电视。系统拒绝角色授权时不会伪装成功或强行改系统。

## 同一台电视的复测

1. 同包名签名覆盖升级，保留来源、NAS与配对。以系统正常显示设置测试；本应用不会替你改密度。
2. 冷启动时钟应显示当前时间；四张观看卡片完整可见。方向键移动并逐一确认，尤其综艺。
3. 首屏按返回，选择留在开视与返回原桌面分别测试。
4. 设置首项申请默认桌面；系统确认后测试HOME、开机、从影视页面回首页，取消授权则仍保留普通应用模式。
5. 若失败，在已授权ADB连接上用 `adb logcat -d -s KaishiHome:I KaishiViewport:I` 获取本应用的尺寸与动作诊断；勿发送包含账户或资源凭证的完整日志。

云端 sharecode 读取已由用户/WorkBuddy另行验证；海报网址问题来自服务端公开地址构造。本版没有再改动已能读取的资源查询参数。目录缓存更新的独立反馈尚未在本轮修复。


## 历史版本复核

[公开源码对照](verification/s90-pre-v30-review.json)覆盖v27、v28、v29、v30和v33。v29与v30的整个网页首页树一致，设计画布1920×1080与观看卡片380×132保持不变。屏保启动导航从v29已有，本次不能称为v30特有的新回归。尚无同一设备的旧版内核、首页模式与显示状态记录，需保留这一限制。
