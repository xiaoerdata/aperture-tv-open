# 创作记录001：从“刷电视桌面”到家庭共享窗

日期：2026-10-23，北京时间。

## 真实决策

用户起初提出小米电视前台系统、开放上传、创新视觉、可二次开发和小红书全过程记录。追问主要任务后，用户选择家庭共享信息屏，目标按Android8+与16:9设计，作为平台首个开源项目。

因此把主价值从艺术屏保转到家庭日程、留言、照片、数据。保留三个场景的视觉吸引力，但所有内容来自同一个家庭空间。采用可退出的应用/桌面候选外壳，型号未知时不承诺刷ROM或替换默认系统。

## 实际实现

从Hub产品脚手架生成起点，移入独立项目的私有接入草稿。独立核心重新组织成模型、存储、业务、HTTP和两个前端。没有修改现有产品业务文件、生产数据库或代理节点。

实现管理员登录、短码申请/批准/领取、电视只读、家人编辑、撤销；写入有revision及幂等回执。照片经Python/Pillow解码并重新编码。原创SVG和Canvas场景替代来源不明的网络图片。

首次1920×1080截图显示拱窗主视觉和侧边日程能够同时阅读。数据山体与标注出现重叠，修改基线。320px手机日期控件撑开Grid，改为真正的窄屏列布局。录制脚本找到场景容器与按钮共用选择器的问题，收紧到button。共享移动控件需要明确primary tone，补齐语义属性后保持统一控件尺寸。

测试最初使用Node fetch重写Host来连接随机测试端口，实际Host未按设想覆盖，导致421。修正测试的HTTP客户端而不是放松应用Host校验；随后隔离HTTP行为通过。首次ffmpeg依赖从默认包索引无法获取，使用PyPI将工具装在临时目录，不改项目运行环境。

## 证据的层次

- 服务端：真实HTTP、独立临时存储，验证鉴权、幂等、冲突、配对、撤销、图片与内容导入。
- 前端：真实Chromium + 真实隔离服务，跨浏览器上下文配对、手机写入、电视轮询回读；手机和电视尺寸检查；错误与草稿检查。
- 媒体：代码逐帧渲染竖屏动画；浏览器录制独立保存。二者都不是电视实拍。
- 原生：仅源码和Manifest审阅；没有SDK、没有构建或真机设备。
- 发布：没有生产部署、公共仓库发布或小红书上传。
